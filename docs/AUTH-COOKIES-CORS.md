# Авторизация: куки и CORS

Фронт отправляет все запросы к API с `credentials: "include"` и ожидает, что бэкенд при логине отдаёт JWT в куке `token`. Если при переходе на админские страницы вас каждый раз выкидывает на страницу входа — скорее всего **кука не уходит на бэкенд** (или не сохраняется после логина).

## Когда так бывает

- **Фронт на одном домене, бэкенд на другом** (например фронт: `http://localhost:3000` или `https://front.example.com`, бэкенд: `https://standart82.ru`).  
  Браузер по умолчанию **не отправляет куки** с одного домена на другой (cross-origin), если бэкенд явно не разрешил это через CORS и правильные атрибуты куки.

## Что должно быть на бэкенде

1. **CORS**
   - Разрешить origin фронта, например:  
     `Access-Control-Allow-Origin: https://standart82.ru`  
     или для локальной разработки:  
     `Access-Control-Allow-Origin: http://localhost:3000`
   - Не использовать `*` вместе с credentials.
   - Обязательно:  
     `Access-Control-Allow-Credentials: true`
   - При необходимости:  
     `Access-Control-Allow-Headers: Content-Type`,  
     `Access-Control-Allow-Methods: POST, GET, OPTIONS`

2. **Кука при логине**
   - Имя: как договорено с бэком (у вас — `token`).
   - Для запросов с **другого домена** (cross-origin) кука должна быть:
     - `SameSite=None`
     - `Secure` (обязательно при `SameSite=None`, значит только HTTPS).
   - `Domain`: либо не указывать (тогда кука привязана к домену бэкенда), либо родительский домен, если фронт и бэк на поддоменах одного домена (например `Domain=.standart82.ru` для `standart82.ru` и `app.new.standart82.ru`).
   - `Path`: лучше широкий, например `/`, чтобы кука уходила на все запросы к бэкенду, включая `/graphql`.

## Рекомендуемый вариант: фронт и бэк на одном домене

Если фронт и бэкенд обслуживаются с **одного домена** (например фронт: `https://standart82.ru`, API: `https://standart82.ru/graphql`):

- Запросы к API считаются same-origin, куки отправляются без возни с `SameSite=None`.
- Достаточно обычных настроек CORS для своего же origin (если бэкенд вообще проверяет origin).

Тогда «при каждом переходе на админские страницы попадаю на страницу входа» обычно исчезает.

## Что проверить в браузере

1. **После успешного логина**  
   DevTools → Application (Chrome) / Storage (Firefox) → Cookies → выбрать домен бэкенда (`standart82.ru`).  
   Должна быть кука (например `token`) с нужными атрибутами.

2. **При переходе в админку**  
   DevTools → Network → найти запрос к `/graphql` (запрос `me` или другой).  
   Во вкладке Request Headers должно быть поле **Cookie** с этой кукой.  
   Если заголовка Cookie нет — браузер не отправляет куку (разные домены без настроенного CORS/куки).

3. **Где крутится фронт**  
   Если фронт открыт с `http://localhost:3000`, а бэкенд на `https://standart82.ru`, без явной настройки CORS и `SameSite=None; Secure` кука на запросы к API не попадёт — будет постоянный редирект на логин при заходе в админку.

## Кратко

- Фронт уже настроен: все запросы к API с `credentials: "include"`.
- Чтобы не выкидывало на логин при каждом заходе в админку, нужно:
  - либо **поднять фронт на том же домене, что и бэкенд** (например `https://standart82.ru`);
  - либо **на бэкенде**: разрешить CORS с origin фронта, `Access-Control-Allow-Credentials: true`, и при логине выставлять куку с `SameSite=None; Secure` (и при необходимости правильный `Domain`).
